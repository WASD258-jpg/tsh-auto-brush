## ✅ 装一次就够 —— 无需再判断版本

站点现在是**双轨**运行，但**本脚本内置两套引擎，会自动识别并启用对应的一套**。

| 地址栏路径 | 实际前端 | 脚本行为 |
| --- | --- | --- |
| `/course_center/...` | 新版「智慧版」（Vue3 + Vite） | 自动启用**新版引擎** |
| `/legacy/...` | 旧站（Angular 7，仍在运行） | 自动启用**旧站引擎** |
| 其他页面 | 首页、课程列表等 | 待命，进入教材后自动启用 |

**你不需要做任何判断，装上就行。**

> **为什么会有两套前端**：站点自 2026-09 起提供新版，但旧站没有下线，只是挪到了 `/legacy/`。
> 登录时由统一认证中心 `uc.izhixue.cn` 按账号属性分流：
>
> ```js
> type: 1-正常登录  2-绑定手机  3-需要跳转到旧外语登录页  4-…  5-账号登录页
> ```
>
> 返回 `type === 3` 的账号会被送往 `/legacy/login`，**全程不签发新站令牌**。
> 因此**同一门课，不同的人可能看到两个完全不同的网站** —— 这正是过去"脚本时好时坏"反馈的根源。

## ✅ 新站已实测（2026-10-08 · 志愿者账号）

此前的版本一直是「代码完整、静态逻辑自洽，但缺少新站实机验证」。
**现已用志愿者提供的学生账号完成登录态实测**，并据实测结果修正了引擎（v2.2.0 修正契约，
v2.3.0 补齐成绩规则与作答策略）。

### 实测环境

| 项 | 值 |
| --- | --- |
| 账号属性 | `userType=6`（学生）、`jumpPlat=0` |
| 落入站点 | **新站** `/course_center/`（未走旧站分流） |
| 页面 | `/course_center/reader/student_course/{bizId}` |

> **顺带纠正一处推断**：此前把「`jumpPlat = 0`」写成被分流旧站的标志，
> 实测该字段为 `0` 的志愿者账号**照样进入新站**，二者并无因果关系。

### 实测结论

一次性核对了此前「尚未在实机证实」的全部假设，结果如下 —— 其中两条**推翻了原设计的前提**：

| 待验证项 | 原文档说法 | 实测结果 |
| --- | --- | --- |
| `questionVOList[].answer` 是否含标准答案 | **会下发** | ❌ 该字段**恒为空**（抽样 40/40） |
| `questionAnswerItemVOList[].answer` 是否含标准答案 | 未区分 | ⚠️ **答错累计到 `errorNumShow` 次后由服务端下发**（本课为 3 次）；答对则回显自己提交的答案 |
| 单选答案是选项 `idx` 而非字母 | 是 `idx`，形如 `"0"`/`"1"` | ⚠️ 是 `idx`，但**形如 UUID**（`"bf9491b2-…"`），不是数字 |
| 填空作答元素是否 `contenteditable` | 待确认 | ✅ 是 `span.zty-exercise-item-fill-blank-do[contenteditable=true]` |
| 分页计数文本 `pagination-text` | 存在 | ✅ 存在，形如 `"25/377"` |
| `.pagination-btn-wrap` 容器 | 计数 span 的兄弟容器 | ❌ **不存在**；计数与两个按钮同挂在 `.preview-pagination` |
| `.option-line` 选择题选项容器 | 关键类 | ❌ 命中 0；实际是 `.ant-radio-wrapper` |
| `.chapter-title` / `.catalog-main` / `.answer-count` | 关键类 | ❌ 命中 0 |
| `content_type` 取值 | 未明确 | ✅ `student_course` 必须用 **2**（用 1 会报 `80020 内容项不存在`） |
| 流式阅读下翻页按钮是否存在 | 待确认 | ✅ 存在（`.pagination-btn` 恒为 2 个） |
| 拖拽题的事件序列（HTML5 DnD vs pointer） | 未在登录态实测 | ✅ **HTML5 DnD 有效**（触发式验证：投放区成功接收 `.dropped-item`） |

### 成绩与得分规则（实测）

课程的 `/course/{id}/detail` 直接给出了判分口径：

| 字段 | 本课取值 | 含义 |
| --- | --- | --- |
| `learnMode` | 1 | **自由模式** |
| `freeShowAnswer` | 1 | 答对即时显示答案与解析；答错达 `errorNumShow` 次后也显示 |
| `errorNumShow` | **3** | **答错 3 次后显示答案与解析**，同时服务端开始下发标准答案 |
| `caculateToGrade` | 1 | 计入成绩 |
| `learnTimeLimit` | 0 | 学习时长限制（**不是计分项**） |

教师端配置界面对两种模式的原文说明：

> **自由模式**：「学生答对即时显示答案与解析，答错 N 次后显示答案与解析，**学习成绩记录末次答题结果**。」
> **闯关模式**：「学生任务过关后显示答案与解析，**学习成绩记录最高答题结果**。」

**这对策略是决定性的**：

- **自由模式记「末次」** → 反复提交**会覆盖**，最后一次的结果就是最终成绩。本课即此模式。
- **闯关模式记「最高」** → 反复提交取最好一次。
- **成绩与时长是两条独立通道**：看板 `overview` 返回 `score` / `progress` / `duration` 三个字段，`duration` 只参与排名，**不进入 `score`**。这与旧站「时长权重更高」是两套规则。

### ⚠️ 作答策略：客观题轮询，主观题用 AI

**站点在答错足够多次后会给出标准答案**，所以拿满分靠的是**轮询取答案**，而不是猜。两条路按题目性质分流（v2.3.0 起）：

| 题目性质 | 服务端行为 | 走哪条路 |
| --- | --- | --- |
| **客观题**（选择 / 判断 / 客观填空 / 拖拽，**含听力选择题**） | 答错到 `errorNumShow` 次后**下发权威 `standardAnswer`** | **轮询**（零 token，比 AI 准） |
| **主观题**（问答 / 写作 / 翻译，`obSub: sub`） | `answerStatus` 恒为 `-1`，**不下发答案** | **AI**（轮询对它无效） |

实测同一道 12 空客观填空题：**AI 首答五空全错，轮询拿到的 12 空全对、得分率 100%，且不消耗 token**。

**关于两种模式**：

| 模式 | 成绩取值 | 反复提交的后果 |
| --- | --- | --- |
| **自由模式** | 记**末次** | 每轮**保持当前最优答案、只补空白**，拿到服务端答案后闭环覆盖，因此是单调改善 |
| **闯关模式** | 记**最高** | 反复提交不会拉低成绩 |

**读不到课程设置时**按最保守处理，不做试错（宁可不做，也不冒险改成绩）。

### 自动连续刷课（跨节推进）

**进课程页点「开始刷课」，它会自己找到进度不足的地方，一节接一节往下刷。**

v2.3.0 之前不是这样——「开始刷课」只在阅读器页面内生效：从目录页点它，
路由解析拿不到内容 id，只闪一行提示就退出，**看起来完全没反应**；
而且一节处理完就停住，不会自己走到下一节。现在补上了：

```
课程页点「开始刷课」
  → 读目录进度，定位第一个未完成的内容
  → 跳到它的阅读器页并作答
  → 做完自动找下一个未完成内容
  → 循环，直到该课程没有未完成项
```

- **跨页靠整页跳转**，状态存在本地，页面重载后自动接着跑（所以你会在地址栏看到逐节跳转）
- **按 `contentId` 判重**，已处理过的不再重复；一个目录下挂多个内容项时会逐个处理
- **连续 3 次未见推进就停下**，避免原地打转
- 随时点「停止」终止，并清掉状态（否则刷新后它会自己又跑起来）

> **在课程列表页用它**：列表页的 URL 和 DOM 里都**没有** courseId（Vue 用编程式路由，
> 数据不挂 DOM），所以脚本读不到。请打开面板「设置」，在 **Course · 课程** 下拉里选定一门；
> 进了课程内页（`/course_center/my_course/{id}/…`）或阅读器页则能自动识别，无需选择。

### 关于「会不会触发反作弊」

实测范围内的结论：**教材阅读器里没有任何行为监控**——全量扫描 282 个前端产物，`textbook-reader-*`
内 `cheat / face / monitor / visibilitychange / blur / fullscreenchange` **全部 0 命中**；
全站也没有 `sendBeacon` 或自建埋点接口。作业/考试模块那套人脸抓拍、切屏提交**不适用于教材阅读**。

真正需要注意的是另外两点：

- **阿里云 RUM 会话回放**：全站开启（`replay: true`、100% 采样），操作节奏会被记录
- **站点没有限流退避**：命中 429 后需要自己冷却，脚本已在 `api()` 层做了本地限流冷却

所以脚本对试错做了**节流**（每次提交间隔随机化）。自由模式与闯关模式**都会**走轮询，
但每轮**保持当前最优答案、只补空白**，拿到服务端答案后闭环覆盖，因此是单调改善。

### 仍然不做的

- **语音题**（口语 / 跟读 / 角色扮演 / 词汇）走驰声实时评测，必须真人录音 —— 脚本**跳过**它。
  注意**跳过不等于完成**，详见下方[已知限制](#-语音题跳过--完成会导致单元进度永久卡住)
- 作业 / 考试模块有全屏监控、切屏提交、人脸抓拍等强反作弊，脚本不触碰

## 新版站点适配说明（引擎 A）

站点已于 2026-09 提供新版：前端从 **Angular 7** 换成 **Vue3 + Vite/rolldown**，
API 从 `www.tsinghuaelt.com/tsenglish/` 迁到独立域名 `zhjyapi.tsinghuaelt.com/elt-user`。

旧版脚本依赖的全部 DOM 结构、路由与接口在新版上均已不存在，功能整体失效
（诊断过程见 [已关闭的 issue #1](https://github.com/WASD258-jpg/tsh-auto-brush/issues/1)，**请勿在该 issue 留言，新反馈请开新 issue**）。

因此**新版引擎**是针对新版站点的**整体重写**，依据来自对线上构建产物的静态逆向，而非猜测：

| 项 | 旧站（引擎 B） | 新版（引擎 A） |
| --- | --- | --- |
| API 域 | `www.tsinghuaelt.com/tsenglish/` | `zhjyapi.tsinghuaelt.com/elt-user` |
| 鉴权 | MD5 签名 + `sea-fetch-path` + AES 专属头 | 单一请求头 `elt-user-token`（令牌在 `localStorage.eltUserToken`） |
| 练习路由 | `/course-study-student/{bookId}/{courseId}/{userId}/{hash}` | `/course_center/reader/{type}/{bizId}?catalogId=&contentId=` |
| 作答模型 | 一页一题 + 右箭头翻页 | 整章滚动 + 题卡内嵌（分页按钮仍在） |
| 时长上报 | hook XHR 抓上报地址后重放 | 直连 `POST /user/study/time/record` |
| 答案来源 | 提交一次 → 读回标准答案 → 修正 → 再提交（试错法） | **站点不下发答案**（实测）→ 走 AI 补答 |

> **⚠️ 此处已按实测修正。** v2.0.0–v2.1.1 曾假定「新版取题接口会把标准答案一并返回」，
> 并据此改为「先取答案 → 一次填对 → 提交」。2026-10-08 登录态实测推翻了这一前提：
> 取题接口的 `answer` 恒为空字符串，**提交响应里的 `answer` 同样为空**。
> 因此旧站的试错法在新站也不成立，答对题目只能依靠 AI 补答（详见上方「新站已实测」）。

### ⚠️ 关于实测状态

**新版引擎**的接口契约、路由格式、题型枚举、DOM 结构，现已**在登录态下完成端到端实测**
（2026-10-08，志愿者学生账号），并据实测结果修正。实测环境与逐条结论见上文
「新站已实测」；证据记录见 [DEVELOPMENT.md](DEVELOPMENT.md)。

实测同时修正了若干**静态逆向的误判**（如 `.pagination-btn-wrap` 实际不存在、

脚本内置 **「结构自检」** 按钮：在阅读器页面点击后，会打印当前路由解析、令牌状态、

**如果功能不生效，请先点「结构自检」，把输出贴到 issue。** 有了这份输出，定位失效点通常只需一次修改。

## 安装

1. 浏览器安装 Tampermonkey（油猴）
2. 打开 Tampermonkey 管理面板 → 新建脚本
3. 粘贴 `tsh-auto-brush.user.js` 全部内容，保存
4. 打开 `www.tsinghuaelt.com` 并登录
5. 进入任意教材/课程，打开具体章节（URL 形如 `/course_center/reader/...?catalogId=...`）

> 已装旧版的用户：Tampermonkey 会依据 `@version` 提示更新；若未提示，
> 在管理面板手动「检查更新」，或重新安装。

| 按钮 | 作用 |

| 做一轮 | 只执行一轮，便于观察行为 |
| 查成绩 | 查询课程学习情况（学生课程页可用） |
| 时长保活（防空闲熔断） | 站点自身每 10 秒上报学习时长，但**空闲满 10 分钟会跳过上报**。此功能周期派发无害的用户活动事件，让站点的计时器保持活跃 |
| 结构自检 | 排错用：打印页面识别、接口返回与 DOM 探针结果 |

推荐流程：登录 → 进入教材/课程 → 打开第一章 → 点「开始刷课」。

> **关于学习时长**：站点本身的设计就是「页面开着 + 有交互」即自动累计，不需要脚本代刷。
> 「时长保活」只是防止挂机 10 分钟后被熔断。这也是为什么它按分钟级而非秒级运行。

## AI 配置（**只给主观题用**）

> **先说结论：客观题根本不需要 AI。**
>
> 服务端对**客观题**在答错累计到 `errorNumShow` 次后会下发权威 `standardAnswer`，
> 脚本轮询即可拿到 —— 实测同一道填空题，AI 首答五个空全错，而轮询拿到的答案
> **12 个空全对、得分率 100%，且零 token 成本**。
>
> **主观题**（`obSub: 'sub'`，如问答 / 写作 / 翻译）才是 AI 唯一必要的场景：
> 服务端对它们**不下发答案**（`answerStatus` 恒为 `-1`，答案字段是
> "Answers will vary." 之类），轮询对它们完全无效。

所以 v2.3.0 起按题目性质分流：

| 题目性质 | 处理方式 | 是否需要 AI |
| --- | --- | --- |
| **客观题**（选择 / 判断 / 客观填空 / 拖拽） | 轮询取服务端权威答案后回填 | ❌ 不需要 |
| **主观题**（问答 / 写作 / 翻译 / `obSub: sub`） | AI 作答 | ✅ 需要 |

**不配 AI 也能跑客观题**：脚本会照常轮询拿答案、推进进度。只有遇到主观题时才会停下提示。

### 配置

面板「设置」→ AI 区：

1. 勾选「启用 AI 补答」
2. API Base URL
3. API Key：你的密钥
4. 模型名
5. 保存（存本地 localStorage，只填一次）

**两种请求格式都支持，按 Base URL 自动识别**：

| 服务 | API Base URL | 模型名示例 | 走的格式 |
| --- | --- | --- | --- |
| DeepSeek（Anthropic 兼容层） | `https://api.deepseek.com/anthropic` | `deepseek-flash`、`deepseek-v4-pro` | Anthropic Messages |
| OpenAI 兼容 | `https://api.deepseek.com/v1` | `deepseek-chat` | `chat/completions` |

> URL 里含 `anthropic` 就按 Anthropic Messages 格式发（`/v1/messages` + `x-api-key`），
> 否则按 OpenAI 格式。末尾带不带 `/v1` 都能识别。

**几个实测踩坑点，这里已经处理掉了**：

- **推理模型会把额度烧在思维链上**：`deepseek-flash` 这类模型默认先输出一大段 `thinking`，
  给 4096 token 会**被思维链吃光、正文一个字都不产出**（`stop_reason: max_tokens`）。
  现已把默认额度提到 16384 —— 注意**不要禁用思维链**，实测禁用后虽然快但答案质量明显下降。
- **超时要放宽**：思维链长时单次请求可达 15s 以上，原 25s 会在复杂题上误判超时，已提到 90s。
- **听力题必须喂原文**：这类题题干在音频里，接口会把原文放在 `attachmentList[].script`，
  脚本已把它连同 `instruction` 一起放进 prompt，否则模型只能瞎猜。

**实测对比**（同一道 12 空的客观填空题）：

| 路径 | 结果 | token 成本 |
| --- | --- | --- |
| AI 首答 | 部分正确甚至全错 | 有 |
| **轮询取答案** | **100%** | **0** |

> **注意**：自由模式下成绩记末次，轮询过程每轮都保持当前最优答案、只补空白，
> 最后用服务端答案闭环覆盖，因此是单调改善。

## 已知限制

### ⚠️ 语音题：跳过 ≠ 完成（会导致单元进度永久卡住）

**脚本会识别语音题并直接跳过，不伪造音频。但这不等于它被完成了。**

| | |
| --- | --- |
| **受影响的题型** | `oral_simple_speak`（口语）、`oral_follow_along`（跟读）、`oral_roleplay`（角色扮演）、`oral_vocabulary_learning`（词汇） |
| **为什么跳** | 走驰声 chivox **实时语音评测**（WebSocket + 麦克风采集 + 服务端打分），必须真人录音。脚本实测：空提交服务端直接返 `HTTP 500`，`answerStatus` 始终缺席 |
| **跳过的后果** | 脚本**会调用 `apiMarkContentDone` 标记该内容已学**，好让流程能继续推进；但语音题本身**拿不到分**（没有提交录音），所以成绩上依然有缺口。这一步对最终分数的确切影响**尚需真机确认** |
| **自动刷课时的行为** | 遇到语音题**不会停**，而是跳过并继续下一节（否则整条链会卡在第一节语音题上）。状态栏会提示「本节 N 题无法自动作答（语音题需真人录音），跳过并继续下一节」|
| **你能做什么** | 想拿满这部分分，只能在浏览器里**手动录一遍**。脚本不会、也不应该代劳——伪造音频既是作弊，也会被评测服务端按「未识别到有效发音」判零 |

> **一句话**：自动刷课能把**客观题**刷满，但**语音题那部分分数永远得你自己补**。
> 这不是 bug 修不掉，是评测机制决定的硬边界。

### 其它

- **答案的获取**：`questionVOList[].answer` 恒为空，标准答案只在**答错累计到 `errorNumShow` 次后**由服务端下发。
  v2.3.0 起已按题型分流——客观题走轮询取权威答案（零 token），主观题才用 AI
- **主观题**（问答 / 写作 / 翻译 / 答案多样的填空）服务端**不下发答案**（`answerStatus` 恒为 `-1`），
  只能靠 AI 作答，且**服务端不自动判分**，最终得分取决于教师批改
- **自由模式下成绩记末次**：反复提交会覆盖，最后一次决定成绩（闯关模式取最高）
- **旧站引擎未更新**：沿用 v1.1.2 逻辑，未针对旧站做过新的适配或验证
- **拖拽类**（新版）的事件序列已按产物还原，且已实测到提交成功
